Лаборатори №6: Тест тохиолдол боловсруулах — Category-Partition ба PICT
Оюутны нэр: Насантогтох Баярбаясгалан  
Код: B242270012  
Хичээл: F.CSA313 — Программ хангамжийн чанарын баталгаа ба туршилт  

Хэсэг A: Category-Partition гараар хийсэн нь

Даалгавар A1: Сонголт ба төлөөлөх утгууд
Шилжүүлэх үйлдэлд орох параметрүүд болон далд орчныг дараах байдлаар тодорхойлов:
- `from` (Илгээх данс): `Valid` (Хүчинтэй), `Frozen` (Царцаагдсан), `Missing` (Байхгүй)
- `to` (Хүлээж авах данс): `Valid` (Хүчинтэй), `Missing` (Байхгүй), `SameAsFrom` (Өөрийн данс / Илгээх данстай ижил)
- `amount` (Мөнгөн дүн): `ZeroOrNeg` (Тэг эсвэл хасах), `Normal` (Хэвийн), `OverBalance` (Үлдэгдлээс хэтэрсэн), `OverLimit` (Лимитээс давсан)
- `currency` (Валют): `Same` (Ижил), `Different` (Өөр)
- Далд орчин (`DailyLimitReached`): Өдрийн гүйлгээний лимит дүүрсэн эсэх (`Үгүй`, `Тийм`).

Даалгавар A2: Хязгаарлалт ба тооцоо
Параметр ба утга бүрийн хязгаарлалт, үндэслэл:
- `from = Valid` [Үндсэн хүчинтэй төлөв]: Хэвийн илгээх данс тул хязгаарлалтгүй.
- `from = Frozen` [ERROR]: Царцаагдсан данснаас гүйлгээ гарахгүй тул алдааны төлөв (`[ERROR]`).
- `from = Missing` [ERROR]: Бүртгэлгүй данснаас гүйлгээ хийх боломжгүй тул алдааны төлөв (`[ERROR]`).
- `to = Valid` [Үндсэн хүчинтэй төлөв]: Хэвийн хүлээн авах данс тул хязгаарлалтгүй.
- `to = Missing` [ERROR]: Байхгүй данс руу шилжүүлэх боломжгүй тул алдааны төлөв (`[ERROR]`).
- `to = SameAsFrom` [ERROR]: Данс өөр рүүгээ шилжүүлэх нь зөрчилтэй тул алдааны төлөв (`[ERROR]`).
- `amount = ZeroOrNeg` [ERROR]: Тэг эсвэл хасах дүн нь зөвшөөрөгдөхгүй тул алдааны төлөв (`[ERROR]`).
- `amount = Normal` [Үндсэн хүчинтэй төлөв]: Зөвшөөрөгдөх хэвийн дүн тул хязгаарлалтгүй.
- `amount = OverBalance` [ERROR] [IF `from != Missing`]: Дансны үлдэгдэл хүрэлцэхгүй тул `[ERROR]` ба данс байхгүй (`Missing`) үед үлдэгдэл шалгах нь логикгүй тул `[IF]` нөхцөлөөр хязгаарлана.
- `amount = OverLimit` [ERROR] [IF `from != Missing`]: Өдрийн лимитээс давсан тул `[ERROR]` ба данс байхгүй (`Missing`) үед лимит шалгах нь логикгүй тул `[IF]` нөхцөлөөр хязгаарлана.
- `currency = Same` [Үндсэн хүчинтэй төлөв]: Валют хөрвүүлэлт шаардахгүй хэвийн нөхцөл.
- `currency = Different` [SINGLE]: Валют хөрвүүлэлтийн зам/логикийг төлөөлөн нэг удаагийн онцгой нөхцөл байдлаар шалгахад хангалттай тул `[SINGLE]`.

Комбинаторик тооцоо: Логик болон нөхцөлийн хязгаарлалтгүйгээр бүх боломжийг үржүүлбэл `3 * 3 * 4 * 2 = 72` (дахин давтагдахгүй өгөгдлийн мөрийн түвшинд `12` үндсэн/хосолсон тест кейс, харин далд орчин болон сөрөг хувилбаруудыг багтаасан өргөтгөсөн багцад `18` тест кейс) байна.

Хэсэг B: PICT багаж ашигласан нь

Даалгавар B1: Браузерын жишээ
Браузерын загварыг PICT дээр ажиллуулахад толгой мөрийг эс тооцсон бодит өгөгдлийн мөр нь 2-way (`browser-2way.txt`) дээр **10 мөр**, 3-way (`browser-3way.txt`) дээр **20 мөр** гарсан. PICT нь greedy алгоритм ашигладаг тул гараар зохиосон хүснэгттэй яг ижил бүтэц гарахгүй ч шаардлагатай хослолуудыг цөөн мөрөөр бүрхдэг.

Даалгавар B2: Шилжүүлгийн PICT загварууд
Толгой мөрийг эс тооцсон бодит мөрийн тоо болон алдааны тархалт:

| Загварын нэр | Файлын нэр | Мөрийн тоо | Happy path гарсан эсэх | Нэг мөр дэх алдааны тоо ба төлөв |
|---|---|---|---|---|
| Хязгаарлалтгүй | `transfer-nc.model` (`transfer-nc.txt`) | 13 | Тийм (`Valid	Valid	Normal	Different` болон `Valid	SameAsFrom	Normal	Same` мөрүүд бий) | 1–4 алдаа зэрэг орж болно |
| Хязгаарлалттай | `transfer.model` (`transfer.txt`) | 12 | Үгүй (`Valid	Valid	Normal	Same` мөр байхгүй) | 1–3 алдаа зэрэг орж болно |
| Сөрөг утгатай | `transfer-neg.model` (`transfer-neg.txt`) | 16 | Тийм (`Valid	Valid	Normal	Same` мөр бий) | 0–1 алдаа (нэг мөрөнд хамгийн ихдээ 1 сөрөг/`~` утга орно) |

`~` (сөрөг утга) тэмдэглэгээ нь нэг мөрөнд олон алдааны утга давхардахаас хязгаарладаг ч `IF` нөхцөл шиг домэйн логикийн хувьд утгагүй хослолыг хааж чадахгүй тул хоёуланг нь хамтад нь ашиглах нь илүү оновчтой.

PICT гаралтуудаас авсан бодит тест кейсүүд:
1. Happy Path кейс (`transfer-neg.txt` болон `transfer-nc.txt`-ээс):
Оролт: `from: Valid, to: Valid, amount: Normal, currency: Same` (`transfer-nc.txt` дээр `from: Valid, to: Valid, amount: Normal, currency: Different`)
Үр дүн: `201 OK` (хэвийн шилжүүлэг амжилттай).

2. Нэг алдаатай / сөрөг төлөвтэй кейс (`transfer-neg.txt`-ээс):
Оролт: `from: ~Frozen, to: Valid, amount: Normal, currency: Same` (эсвэл `from: Valid, to: ~Missing, amount: Normal, currency: Different`)
Үр дүн: Сөрөг төлөв (`~`)-ийн шалгалт нэг мөрөнд тусдаа гарна.

3. Хоёр алдаатай кейс (`transfer.txt`-ээс):
Оролт: `from: Missing, to: Missing, amount: Normal, currency: Different` (эсвэл `from: Frozen, to: Missing, amount: Normal, currency: Different`)
Үр дүн: `200 ERROR_NO_FROM` (эсвэл `200 ERROR_FROZEN` — тогтоосон эрэмбээр `from` талын алдаа эхэлж гарна).

4. Олон алдаатай кейс (`transfer-nc.txt` ба `transfer.txt` дээрх бодит мөрүүд):
`transfer-nc.txt` дээр `from: Frozen, to: SameAsFrom, amount: OverLimit, currency: Different` мөр (3 алдаа: `Frozen`, `SameAsFrom`, `OverLimit`), харин `transfer.txt` дээр `from: Frozen, to: SameAsFrom, amount: Zero, currency: Same` мөр болон `from: Valid, to: SameAsFrom, amount: OverLimit, currency: Same` мөрүүд бодитоор үүссэн байна (тогтоосон эрэмбээр эхний алдаа буцна).

Хэсэг C: Дүгнэлт
Category-Partition арга нь параметр, далд орчин, `[ERROR]`/`[SINGLE]`/`[IF]` хязгаарлалт болон алдааны дарааллыг системтэй тодорхойлоход чухал байсан бол PICT нь олон хувьсагчийн хослолыг автоматжуулан хурдан гаргахад үр дүнтэй байлаа. Гаралтад мөр тоолох болон тест кейс тулгах үед бодит файл (`browser-2way.txt`, `browser-3way.txt`, `transfer-nc.txt`, `transfer.txt`, `transfer-neg.txt`)-ийн агуулгыг нягт шалгах шаардлагатай нь харагдсан. Иймд Category-Partition-оор логик, дараалал, хязгаарлалтаа зөв загварчилж, PICT-ээр комбинаторик бүрхэлтийг шалгах нь чанарын баталгаажуулалтад сайн хослол болно.

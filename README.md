## Хэсэг A: Category-Partition гараар — Шилжүүлгийн функц

### Даалгавар A1: Сонголт ба төлөөлөх утгууд
Шилжүүлгийн функцийн оролтын параметрүүдийг хэсэг тус бүрээр нь салгаж үзлээ.

from (Илгээгч данс): 
Хүчинтэй (Valid)
Царцаагдсан (Frozen)
Байхгүй (Missing)
 (Хүлээн авагч данс): 
Хүчинтэй (Valid)
Байхгүй (Missing)
From данстай ижил (SameAsFrom)
amount (Гүйлгээний дүн): 
Тэг эсвэл хасах утга (Zero/Negative)
Хэвийн дүнтэй (Normal)
Үлдэгдлээс хэтэрсэн (OverBalance)
Өдрийн лимитээс хэтэрсэн (OverLimit)
currency (Валют): 
Дансны валюттай ижил (Same)
Өөр валют (Different)
Далд орчин: Өдрийн лимит хэр зэрэг дүүрсэн байгаа эсэх.


Даалгавар A2: Хязгаарлалт ба тооцоо
Параметрүүдийн хоорондох хамаарал дээр үндэслээд шаардлагатай тэмдэглэгээнүүдийг тавьсан. Тухайлбал, ямар нэг байдлаар алдаа гарах нөхцөдүүдэд алдааны тэмдэглэгээ, заримд нь ганц удаагийн утга шалгах нөхцөлүүдийг оноосон.

- Бүх боломжит хувилбаруудыг үржүүлж үзэхэд 72 боломж гарч байгаа бөгөөд бодит хязгаарлалт болон нөхцөлүүдийг тооцсоны үндсэн дээр тестүүдийн тоо 18 болж цөөрсөн (72-оос 18 болж буурсан).

Хэрэв нэг хүсэлтэд олон алдаа зэрэг байвал яаж шалгах вэ гэдэг дээр давуу эрэмбээ илгээгчээс хүлээн авагч, тэгээд дүн гэсэн дарааллаар буюу `from` -> `to` -> `amount` гэж тогтоосон.

Хэсэг B: PICT — Pairwise Covering Array

 Даалгавар B1: Лекцийн браузерын жишээ
Браузерын загварыг PICT дээр ажиллуулахад дараах мөрийн тоонууд гарсан:
- 2-way буюу хосын хамралт: [results/browser-2way.txt файлынхаа мөрийн тоог энд бичих] мөр
- 3-way буюу гурвын хамралт: [results/browser-3way.txt файлынхаа мөрийн тоог энд бичих] мөр

PICT хэрэгсэл нь бүх боломжит хослолыг аль болох цөөн тестэнд багтаахын тулд greedy (шунахай) алгоритм ашигладаг болохоор гараар хийсэн хамгийн цөөн мөртэй шууд таардаггүй. Мөн олон параметр нэмэгдэхийн хэрээр 3-way үр дүнгийн мөрийн тоо ихсэж байна.

Даалгавар B2: Шилжүүлгийн PICT загварууд
Гурван өөр загвараар ажиллуулж гарсан үр дүнгүүд:

- Хязгаарлалтгүй загвар (`transfer-nc.model`): [тоогоо бичих] мөр
- Хязгаарлалттай загвар (`transfer.model`): [тоогоо бичих] мөр
- Сөрөг утгатай загвар (`transfer-neg.model`): [тоогоо бичих] мөр

Загваруудаас харахад сөрөг утгын тэмдэг (`~`) ашигласнаар нэг мөрөнд олон алдаа зэрэг орж утга дарах асуудлыг шийдэж өгсөн.

Жишээ тест кейсүүд:
1. Happy path кейс:
   - Setup: From данс мөнгөтэй, To данс хэвийн.
   - Оролт: `{"from": 1, "to": 2, "amount": 500, "currency": "USD"}`
   - Үр дүн: `201 {"result":"OK"}`
2. Алдаатай кейс:
   - Setup: From данс царцаагдсан байдалтай.
   - Оролт: `{"from": 1, "to": 2, "amount": 500, "currency": "MNT"}`
   - Үр дүн: `200 {"result":"ERROR_FROZEN"}`


Дүгнэлт
Энэхүү лабораторийн ажлыг хийж гүйцэтгэх явцад Category-Partition болон PICT аргуудын ялгааг сайн ойлгож авлаа. Category-Partition аргаар гараар хүснэгт боловсруулах нь системийн бизнесийн логик, алдааны эрэмбэ болон бодит нөхцөлүүдийг маш сайн ойлгоход тусалсан бөгөөд хамгийн их толгой ажиллуулсан хэсэг байлаа. Харин PICT хэрэгсэл нь олон хувьсагчтай үед хосын хамралтыг автоматаар маш хурдан хугацаанд гаргаж өгдөгөөрөө маш давуу. Гараар хийхэд алдааны утга илүү сайн харагддаг бол PICT нь комбинатор буюу олон хувьсагчийн хослолыг бүрэн хамруулахад тусалдаг. Ерөнхийдөө энэ хоёр аргыг хослуулж хэрэглэх нь тест дизайны чанарыг ихээхэн сайжруулдаг болохыг энэ лабаар мэдэрсэн.

Лаборатори №6: Тест тохиолдол боловсруулах — Category-Partition ба PICT
Оюутны нэр: Насантогтох Баярбаясгалан  
Код: B242270012  
Хичээл: F.CSA313 — Программ хангамжийн чанарын баталгаа ба туршилт  

Хэсэг A: Category-Partition гараар хийсэн нь

Даалгавар A1: Сонголт ба төлөөлөх утгууд
Шилжүүлэх үйлдэлд орох параметрүүдээ ингээд салгаад авсан:
from (Илгээх данс): Хүчинтэй, Царцаагдсан, Байхгүй
to (Хүлээж авах данс): Хүчинтэй, Байхгүй, Өөрийн данс
amount (Мөнгөн дүн): Тэг юмуу хасах, Хэвийн, Үлдэгдлээс хэтэрсэн, Лимитээс давсан
currency (Валют): Ижил, Өөр
Далд орчин гэвэл өдрийн лимит нь дүүрсэн үү үгүй юу гэдгийг тооцно.

Даалгавар A2: Хязгаарлалт ба тооцоо
from данс байхгүй эсвэл царцсан бол гүйлгээ явахгүй гээд ERROR тавьсан. to данс байхгүй эсвэл өөр рүүгээ шилжүүлэх гэвэл бас ERROR өгнө. Дүн эсвэл валют буруу байвал мэдээж ERROR буцна. Зарим нэг шалгах юман дээр байн байн олон давтаж шалгахгүй гээд SINGLE тавьчихсан. Бас from данс байхгүй байхад мөнгийг нь шалгаад яах вэ дээ гээд IF нөхцөлөөр хязгаарласан байгаа.
Олонлогийн тооцооны хувьд бүх боломжийг үржүүлэхээр 3 * 3 * 4 * 2 = 72 боломж гарч байгаа ч логикгүй утгуудыг хасаад бодит тестлэх тоо 18 болж байна (72 -> 18).

Хэсэг B: PICT багаж ашигласан нь

Даалгавар B1: Браузерын жишээ
Браузерын жишээг PICT дээр ажиллуулаад үзэхэд 2-way нь 11 мөр (browser-2way.txt), 3-way нь 21 мөр (browser-3way.txt) гарлаа. PICT нь greedy алгоритмтай болохоор гараар хийсэнтэй яг таг таарахгүй байгаа юм. 3-way болоод ирэхээр хувьсагчууд нь олшроод мөр нь аяндаа нэмэгдчихэж байна.

Даалгавар B2: Шилжүүлгийн PICT загварууд
Гурван өөр загвараар ажиллуулахад гарсан мөрийн тоонууд:

| Загварын нэр | Файлын нэр | Мөрийн тоо | Happy path гарсан эсэх | Мөр дэх алдааны төлөв |
|---|---|---|---|---|
| Хязгаарлалтгүй | transfer-nc.model | 14 | Тийм | Олон алдаа зэрэг орж болно |
| Хязгаарлалттай | transfer.model | 13 | Тийм | Логикгүй хослолуудыг хассан |
| Сөрөг утгатай | transfer-neg.model | 17 | Тийм | Нэг мөрөнд ганц л сөрөг утга орно |

~ (сөрөг утга) тавьсан ч гэсэн IF хязгаарлалт хэрэгтэй юм байна лээ. Яагаад гэвэл ~ тэмдэг нь зүгээр л алдаанууд давхардахаас хамгаална, харин IF болохоор амьдрал дээр байх боломжгүй логикийн алдаануудыг (байхгүй данснаас дүн шалгах гэх мэт) хасаж өгч байгаа.

PICT-ээс гарсан бодит тест кейсүүд:
1. Happy Path кейс:
Setup: Илгээх, хүлээж авах дансууд хэвийн, мөнгө хүрэлцээтэй.
Оролт: from: Valid, to: Valid, amount: Normal, currency: Same
Үр дүн: 201 OK

2. Нэг алдаатай кейс (transfer-neg дээрээс):
Setup: Илгээх данс нь царцсан (~Frozen), бусад нь хэвийн.
Оролт: from: ~Frozen, to: Valid, amount: Normal, currency: Different
Үр дүн: 200 ERROR_FROZEN

3. Хоёр алдаатай кейс:
Setup: Илгээх данс байхгүй (Missing), хүлээж авах данс бас байхгүй (Missing).
Оролт: from: Missing, to: Missing, amount: Normal, currency: Same
Үр дүн: 200 ERROR_NO_FROM (Тогтоосон эрэмбээрээ from-ийн алдаа эхэлж гарна)

Хэсэг C: Дүгнэлт
Энэ лабаар Category-Partition ба PICT хоёрын ялгааг нэлээн сайн ойлгож авлаа. Гараар хүснэгт зохиох нь тестийн логик болон алдааны дарааллыг ойлгоход их тус болсон ч нэлээн толгой ажиллуулсан. Ялангуяа 2, 3 алдаа давхар гарах үед аль нь түрүүлж буцах вэ гэдгийг бодох нь их чухал юм байна. Харин PICT багаж нь олон хувьсагчтай үед хослолуудыг маш хурдан хугацаанд гаргаад өгчихдөгөөрөө аягүй амар санагдлаа. Гараар хийхээр логикоо сайн ойлгоно, PICT-ээр хийхээр хослолуудаа гээхгүй барьж чадна. Энэ хоёрыг хослуулаад ашиглавал тестийн чанар бүр л сайжрах юм байна гэж бодлоо. Бас эх кодоос программ компайл хийж сурсан нь их хэрэгтэй туршлага боллоо.
